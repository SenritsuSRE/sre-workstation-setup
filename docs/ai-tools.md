# AI Tools Operation & Security Guide / AIツール運用・安全ガイド

本ドキュメントでは、SREワークステーションにおける AI 支援ツール（Claude Code 等）の安全な運用ポリシーおよび、インフラストラクチャ運用におけるベストプラクティスを定義します。

---

## 1. AIツール運用の基本哲学

本リポジトリにおけるAIツール活用は、単なるコード生成の効率化に留まらず、システムの安全性と信頼性を高めるための**「安全なペアプログラミングパートナー」**としての位置づけを持ちます。

1. **Safety First (人間による最終確認)**: AIが生成したコードやインフラ変更（AWS CDK, Terraform等）は、人間が必ずレビュー・検証を行ってから適用する。
2. **Secret Hygiene (機密情報の保護)**: APIキー、パスワード、社内機密情報をAIのコンテキスト（プロンプト）に誤って含めない。
3. **Reproducibility (再現性の担保)**: AIに依存した暗黙的な手順ではなく、誰でも再現・検証可能なスクリプトやドキュメントとして成果を残す。

---

## 2. Claude Code の基本設定と利用方針

ターミナルベースで動作する Claude Code は、ローカル環境のファイル操作やコマンド実行を伴うため、以下の点に注意して運用します。

### セキュリティチェックリスト
- **`.gitignore` および `.dockerignore` の徹底**: 機密ファイル（`.env`, `*.pem`, `~/.aws/credentials` 等）がAIの読み取り範囲外になっていることを確認する。
- **機密情報のマスキング**: ログやエラー出力などをプロンプトに貼り付ける際は、アカウントID、IPアドレス、トークン等の機密情報が含まれていないか目視で確認し、必要に応じてマスクする。

---

## 3. インフラ・コード生成時のガイドライン

AWS CDK や自動化スクリプトをAIに記述させる際は、以下の制約を明示的に指示または遵守させます。

- **破壊的変更の防止**: `DeletionPolicy: Retain` や `RemovalPolicy.DESTROY` の安易な使用を避け、本番環境のデータ損失を防ぐ設計にする。
- **最小権限の原則**: IAMポリシー等を生成させる際、過剰な権限（`*`）を付与する記述になっていないか厳しくレビューする。
- **Lint / Biome による静的検証**: 生成されたコードは必ず Biome や各言語のリンターを通し、品質を担保する。

---

## 4. トラブルシューティングとエスカレーション

AIツール利用時に予期せぬエラーやセキュリティ上の懸念が生じた場合の対応手順です。

1. **即座のセッション中断**: 機密情報のリークや不審な挙動を検知した場合は、速やかにAIセッションを終了する。
2. **影響範囲の確認**: ローカル環境やAWSリソースに対して不正な変更が行われていないか、`git status` や `aws` コマンドで確認する。
